## Architecture / proposed approach
ใช้ CLI `kt404-youtube.exe` ที่มีอยู่แล้วใน repo โดยแก้โค้ดเล็กน้อยเพื่อเพิ่ม `#shorts` ในชื่อคลิปแนวตั้ง: รัน `profile list` เพื่อยืนยันโปรไฟล์ → แก้ `_vertical_short_hashtags` ใน `media.py` เพื่อเพิ่ม `#shorts` (TDD: เขียน test ที่ล้มก่อน แล้วแก้โค้ดให้ผ่าน) → รัน `dry-run` เพื่อตรวจไฟล์ → รัน `upload --profile katy404 --folder ... --channel ... --schedule-from "2026-10-13T07:30:00+07:00"` เพื่ออัปโหลดและตั้งเวลาเผยแพร่ผ่าน API แบบ `private` + `publishAt` → รายงานผลจาก CLI output

```python
def _vertical_short_hashtags(candidate: MediaCandidate, profile: UploadProfile) -> list[str]:
    channel_name = _hashtag_text(profile.channel_alias)
    if not channel_name:
        raise MetadataError("channel_alias cannot be converted to a channel hashtag")

    hashtags = [f"#{channel_name}", "#vtuberth"]
    game_hashtag = _game_hashtag(candidate.path)
    if game_hashtag:
        hashtags.append(game_hashtag)
    hashtags.append("#วันว่างๆ")
    hashtags.append("#shorts")
    return hashtags
```

## Risks, tradeoffs, and open questions
- **ความเร็วเน็ต / เวลาอัปโหลด:** 28 GB อาจใช้เวลาหลายชั่วโมง ถ้าเน็ตช้าหรือตัดกลางคัน อาจต้องรันใหม่ (uploader มี state store ที่ `state.sqlite3` ช่วยให้ resume ได้บางส่วน)
- **YouTube API quota:** อัปโหลดจำนวนมากในครั้งเดียวอาจชน quota limit ถ้าเกิด error ให้รายงานและหยุด ไม่ต้องลองแก้ตัวเอง
- **ไฟล์ `.mp4` 1 ตัว:** `หนีฝ่าความหนาว_Minecraft-vdo_9x16.mp4` — scanner รองรับ `.mp4` แล้ว แต่ต้องตรวจสอบว่า ffprobe อ่านได้หรือไม่ ถ้าอ่านไม่ได้จะถูกข้าม
- **OAuth scope:** ถ้า token หมดอายุหรือไม่มี scope ที่จำเป็น ต้องทำ consent flow ใหม่ (เปิด browser) — ทำได้เฉพาะตอนอัปโหลดจริงเท่านั้น
- **ความเสี่ยงเรื่อง privacy:** ตั้งเป็น `private` + `publishAt` ผ่าน API เท่านั้น ห้ามเปลี่ยนเป็น public ก่อนเวลา และห้ามใช้ `api_audit_passed` เป็นตัวตัดสิน
- **การแก้โค้ด:** การเพิ่ม `#shorts` ใน `_vertical_short_hashtags` จะส่งผลต่อทุกคลิปแนวตั้งที่อัปโหลด ต้องตรวจสอบว่า test ครอบคลุมกรณีที่มี game_hashtag และไม่มี game_hashtag
